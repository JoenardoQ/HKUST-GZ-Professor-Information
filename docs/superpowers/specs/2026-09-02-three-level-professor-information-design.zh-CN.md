# 三级教授信息数据设计

日期：2026-09-02

## 目标与范围

本仓库是公开三级教授信息体验经过审核的数据事实源。仓库必须发布轻量教授目录、每位教授的一份个人资料文档和一份论文文档。研究细分方向及其解释只能在论文检索与去重完成后生成。先生成并冻结英文，再从冻结后的英文结构翻译中文。

论文工作流不得将 Google Scholar 用作论文来源。官方资料中的 Scholar 标识符可以保留为身份字段，但不得用于提供论文证据或支撑研究细分方向结论。

## 公开数据契约

发布版本使用 manifest schema version 2，并提供：

| 层级 | 产物 | 内容 |
| --- | --- | --- |
| 一级 | `data/directory-index.json` | 用于检索的轻量身份、隶属关系、联系方式、研究字段、数量及核验日期 |
| 二级 | `professors/<group>/<slug>.md` 与 `.zh-CN.md` | 基本信息、研究领域、关键词、研究细分方向，以及每个细分方向恰好三句话的解释 |
| 三级 | `professors/<group>/<slug>.publications.md` 与 `.publications.zh-CN.md` | 发布窗口内检索到的全部论文，并在每篇论文后以小字标注对应的生成研究细分方向 |

`data/search-index.json` 继续作为完整的离线分析发布产物保留。网站不得在请求期间读取它。

manifest 中每位教授的条目包含四个列入白名单的文档路径：

```json
{
  "profile": { "en": "...md", "zhCN": "...zh-CN.md" },
  "publications": { "en": "...publications.md", "zhCN": "...publications.zh-CN.md" }
}
```

## 研究分析契约

论文检索与去重完成后，每位教授获得一组有序的 `researchSubdirections`。每一项包含：

- 作用域限定于该教授的稳定 ID；
- 英文名称；
- 三句分别存储、未经任意拼接的英文解释；
- 支撑该解释的论文 ID 与获准使用的证据 URL；
- `pass`、`limited` 或 `block` 审核状态。

每篇论文获得零个或多个 `generatedSubdirectionIds`。这些 ID 必须能解析到同一位教授的研究细分方向。证据不足以支持可靠归类时，论文保持未归类，其渲染备注明确说明无法进行可靠的生成细分方向归类。系统不得强行建立错误关系。

对于检索论文不足的教授，可以使用公开的官方研究信息支撑细分方向。三句话必须分别说明已知研究领域、现有可验证依据和证据局限，禁止没有依据的具体化扩写。

## 英文优先生成

固定执行顺序如下：

1. 获取官方教授名单；
2. 从获准来源检索论文；
3. 去重并隔离冲突；
4. 将论文关联到教授身份；
5. 生成英文研究领域、关键词、细分方向、三句话解释及论文与细分方向的关联；
6. 审核每一条生成的英文记录；
7. 生成英文个人资料 Markdown、英文论文 Markdown 和两个索引；
8. 冻结英文结构化数据及文件摘要；
9. 仅将英文展示文本翻译成中文；
10. 使用经过审核的翻译记忆生成中文 Markdown；
11. 验证中英文结构一致性，并且只发布零阻断项的版本。

中文生成不得新增、删除、重排、合并或拆分研究细分方向、解释句、论文、标识符或证据链接。

## Codex 自审门禁

逐条用户人工批准不再是发布依赖。Codex 执行完整审核，并写入机器可读的发布报告。确定性校验覆盖每一条记录：

- 每个研究细分方向恰好包含三个非空句子；
- 所有引用的论文 ID 与细分方向 ID 均解析到同一位教授；
- 每项结论都具有获准使用的证据 URL，或明确标注证据局限；
- 拒绝重复或近似重复的研究细分方向；
- 论文备注只能包含已知细分方向或未归类说明；
- 中英文结构、顺序、ID、URL 和论文身份保持一致；
- 不得出现 Google Scholar 论文证据 URL；
- manifest 选择的四份文档全部存在，且不超过公布的大小限制。

语义审核将每位教授标记为 `pass`、`limited` 或 `block`。`limited` 记录只能连同明确的证据局限一起发布。任何 `block`、未解决冲突、错误翻译或缺失产物都会阻止发布。

## 定时更新工作流

Codex 针对每年 3 月 1 日和 9 月 1 日截止日期运行工作流。生成的候选产物与审核报告提交到功能分支。全部门禁通过后，审核后的产物合并到 GitHub `main`。网站只读取 `main`，因此常规数据更新无需重新部署网站。

## 仓库文档与测试

`README.md`、`README.zh-CN.md`、工作流文档、schema、生成器测试、验证器测试和运维命令必须描述一致的 schema version 2 契约。测试覆盖确定性生成、非法证据关联、句子数量、未归类论文、中英文一致性、路径白名单和可复现输出。
